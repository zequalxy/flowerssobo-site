# Flowerssobo — сайт цветочной студии

Одностраничный сайт флористической студии **Flowerssobo** (Липецк): авторские букеты
из сезонных цветов с доставкой за 60–90 минут. Живой сайт: [flowerssobo.ru](https://flowerssobo.ru).

## Что внутри

- **Hero с фоновым видео** — цветочный прелоадер, устойчивый автоплей
  (повтор `play()` по первому жесту и возврату на вкладку, страховочный таймаут).
- **Витрина с поштучным ценообразованием** — у монобукетов селектор количества
  стеблей, цена пересчитывается на лету; доплата за упаковку (коробки L/XL)
  подставляется автоматически; «витринное» округление цен вверх до `…90`.
- **Каталог-коллаж** (бенто-сетка), секция сезонности, FAQ-аккордеон,
  бесконечная карусель отзывов с ручным drag/свайпом и инерцией.
- **Форма заявки → Posiflora + Стебель + Telegram**: заказ создаётся в
  Posiflora (JSON:API, `POST /v1/orders`), копия — новым заказом в Стебле,
  CRM магазина (Connect JSON, `CreateSiteOrder`), в Telegram уходит
  уведомление с номером документа. Без Posiflora хранилищем заявки
  становится Стебель. zod-валидация на клиенте и сервере, honeypot,
  rate-limit (5 заявок / 10 минут / IP), аккуратные состояния ошибок.
- **SEO**: метаданные, OG-картинка, JSON-LD (Florist + FAQPage), robots,
  sitemap, фирменный favicon через `ImageResponse`.
- **Безопасность**: CSP и набор security-заголовков, лимит размера тела
  запроса, секреты только в env.

## Запуск

```bash
npm install
cp .env.example .env.local   # подставьте свои значения
npm run dev                  # http://localhost:3000
```

Переменные окружения (см. `.env.example`):

- `POSIFLORA_API_URL` — база API **вместе с `/api`**, например
  `https://ваш-аккаунт.posiflora.com/api`; `POSIFLORA_USERNAME` и
  `POSIFLORA_PASSWORD` — учётка; `POSIFLORA_STORE_ID` — UUID точки продаж
  (обязателен, если интеграция включена); `POSIFLORA_SOURCE_ID` и
  `POSIFLORA_WORKER_ID` — источник заказа и сотрудник-создатель,
  необязательные (сотрудник по умолчанию берётся из сессии);
  `POSIFLORA_DOC_PREFIX` — префикс номера документа (по умолчанию `site`).
  Где взять UUID — ниже, «Как найти идентификаторы Posiflora»;
- `STEBEL_API_URL` — база API Стебля **вместе с `/api`**, только
  `https://` (`http://` — лишь для localhost), например
  `https://stebel.example.ru/api`; `STEBEL_SITE_KEY` — ключ сайта из
  Стебля (Настройки → Сайт → «Создать ключ», показывается один раз).
  Подробнее — ниже, «Стебель»;
- `TELEGRAM_BOT_TOKEN` — токен бота, которому уходят уведомления;
- `TELEGRAM_CHAT_ID` — chat_id получателя; несколько — через запятую;
- `TELEGRAM_NOTIFY_ONLY` — `1`, если заявки хранятся в Posiflora или
  Стебле: тогда в Telegram уходит только уведомление «новая заявка» с
  номером заказа, без персональных данных. Если заказ создан и в Стебле, в
  уведомлении есть ссылка «Открыть в Стебле» (только для `https://`
  адреса): детали по ней видны только после входа (Telegram ждёт Стебель до
  2 секунд, не успел — уведомление уходит без ссылки). **Включать только там, где
  интеграция с Posiflora или Стеблем действительно работает** — без них
  сайт отказывает в приёме заявки, чтобы она не потерялась молча;
- `TELEGRAM_API_BASE` — необязательно: адрес прокси/зеркала Bot API, если
  хостинг не выпускает трафик к `api.telegram.org` напрямую.

Если переменные Posiflora или Стебля не заданы, соответствующая интеграция
считается выключенной. Без обеих заявка уходит только в Telegram. Без
Telegram-переменных сайт тоже работает, но если не подключены ни Posiflora,
ни Стебель, отправка формы вернёт ошибку.

Продакшен-сборка: `npm run build && npm start`. Линт: `npm run lint`.

## Как найти идентификаторы Posiflora

В личном кабинете UUID точки продаж и источника заказа не показываются —
их отдаёт API. Достаточно логина и пароля.

**1. Логин.** В ответе нужен `data.attributes.accessToken`; заодно там
лежит `data.relationships.worker.data.id` — сотрудник, который
подставится в `createdBy`, отдельная переменная для него не нужна:

```bash
curl -sS -X POST "https://ваш-аккаунт.posiflora.com/api/v1/sessions" \
  -H "Content-Type: application/vnd.api+json" \
  -H "Accept: application/vnd.api+json" \
  -d '{"data":{"type":"sessions","attributes":{"username":"ЛОГИН","password":"ПАРОЛЬ"}}}'
```

**2. Справочники** — подставьте токен из первого шага. Точки продаж дадут
`POSIFLORA_STORE_ID`, источники — `POSIFLORA_SOURCE_ID`:

```bash
TOKEN="вставьте_accessToken"
BASE="https://ваш-аккаунт.posiflora.com/api"

curl -sS "$BASE/v1/stores"        -H "Accept: application/vnd.api+json" -H "Authorization: Bearer $TOKEN"
curl -sS "$BASE/v1/order-sources" -H "Accept: application/vnd.api+json" -H "Authorization: Bearer $TOKEN"
curl -sS "$BASE/v1/workers?activeOnly=true" -H "Accept: application/vnd.api+json" -H "Authorization: Bearer $TOKEN"
```

**3. Источник «Сайт»**, если его ещё нет. UUID придумываете сами — API
принимает клиентский идентификатор и возвращает его же:

```bash
curl -sS -X POST "$BASE/v1/order-sources" \
  -H "Content-Type: application/vnd.api+json" \
  -H "Accept: application/vnd.api+json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"data":[{"type":"order-sources","id":"ПРИДУМАННЫЙ-UUID","attributes":{"title":"Сайт"}}]}'
```

Access-токен живёт около часа — для разовой настройки этого хватает.
Учтите, что пароль из команды логина останется в истории оболочки:
после настройки историю стоит почистить.

```bash
docker build -t flowerssobo .
docker run -p 3000:3000 \
  -e POSIFLORA_API_URL=... \
  -e POSIFLORA_USERNAME=... \
  -e POSIFLORA_PASSWORD=... \

  -e STEBEL_SITE_KEY=... \
  -e TELEGRAM_BOT_TOKEN=... \
  -e TELEGRAM_CHAT_ID=... \

  flowerssobo
# TELEGRAM_NOTIFY_ONLY=1 — только при подключённой Posiflora или Стебле (см. выше).
# STEBEL_* на боевом сайте — только после правки юридических текстов (см. «Стебель»).
```

Multi-stage образ на `node:22-alpine` со standalone-выводом Next
(итоговый слой — только `server.js`, статика и `public/`), запуск от
непривилегированного пользователя. Секреты в образ не попадают —
только через переменные окружения при запуске.

## Стебель

Стебель — CRM магазина. Каждая заявка с формы становится там новым заказом:
этап «Новый», источник «Сайт», точка — та, что выбрана при выдаче ключа.
Сотрудникам, включившим в Стебле уведомления, приходит push «Новый заказ
№ N с сайта».

**Подключение.**

1. В Стебле владелец открывает Настройки → Сайт → «Создать ключ», называет
   подключение (например, «Сайт flowerssobo.ru») и выбирает точку. Ключ вида
   `stebel_site_…` показывается **один раз** — сразу перенесите его в
   `STEBEL_SITE_KEY`. Потеряли — отзовите ключ там же и создайте новый.
2. `STEBEL_API_URL` — адрес Стебля **вместе с `/api`**:
   `https://stebel.example.ru/api`. Без `/api` Стебель ответит 404/405, и в
   логе сайта будет подсказка.
3. Перезапустите сайт и отправьте заявку с формы — заказ появится в списке
   заказов Стебля.

**Что уходит в Стебель:** `customerName` — ФИО, `customerPhone` — телефон,
`wish` — «что нужно», `comment` — комментарий, `contactPreference` — способы
связи с ником, приклеенным к Телеграму («Телеграм @anna, WhatsApp»),
`externalRef` — номер заявки в Posiflora («Посифлора site53da7243»), если она
там создана, `consent` — отметка о согласии с редакцией документов. IP
покупателя не передаётся. Запрос идёт с сервера сайта, браузер покупателя
Стебля не видит, ключ в браузер не попадает.

**Сбои.** На попытку — 8 секунд; на сетевой сбой, таймаут и 5xx — один
повтор с тем же `requestId` и тем же телом (Стебель вернёт уже созданный
заказ, а не заведёт второй); обе попытки укладываются в 10 секунд. На
ошибки ключа, полей и лимита (100 заявок в час на ключ) повтора нет. Ключ
вычищается из всех сообщений в логе.

> **Юридическое условие — до включения `STEBEL_*` на боевом сайте.**
> Положение о конфиденциальности (`/privacy`) и Согласие на обработку ПДн
> (`/consent`) сейчас называют получателями данных только Posiflora
> (ООО «Лукасофт») и курьерские службы. Прежде чем заявки с боевого сайта
> пойдут в Стебель, в этих документах должны появиться Стебель (его
> оператор) и хостинг, на котором он работает, — как получатели данных или
> обработчики по поручению оператора. Тексты подготовлены юристом владельца
> и перенесены дословно: правит их только юрист, а после правки нужно
> обновить `site.privacyRevision` в `lib/site.ts`. До тех пор `STEBEL_*`
> включаются только на тестовой копии сайта.

## Заметки по реализации

- **Маршрут заявки.** `POST /api/order` сначала создаёт заказ в Posiflora и
  только потом параллельно шлёт уведомление в Telegram и копию в Стебель.
  Если Posiflora вернула ошибку, клиент видит ошибку — заявки нет, и в
  Стебель она не уходит (иначе повтор клиента задвоил бы её там). Если заказ
  создан, а Telegram или Стебель отвалились, клиент видит успех (заказ-то на
  месте), а сбой уходит в лог. Когда Posiflora не настроена, хранилищем
  становится Стебель. С `TELEGRAM_NOTIFY_ONLY=1` заявка сначала уходит в
  него, и сбой Стебля означает ошибку для клиента; сигнал в Telegram с
  номером заказа Стебля ответ ждёт не дольше 12 секунд от начала запроса к
  Стеблю (форма ждёт 15), не успевший досылается после ответа. Без флага
  Стебель и Telegram идут почти параллельно (Telegram ждёт номер Стебля до
  2 секунд), и заявка принята, если дошла до Стебля или до Telegram. Когда
  не настроены ни Posiflora, ни Стебель, Telegram остаётся единственным
  адресатом, и его сбой означает ошибку для клиента.

  | Posiflora | Стебель | `TELEGRAM_NOTIFY_ONLY` | Что происходит |
  | --- | --- | --- | --- |
  | заказ создан | любой | любой | Telegram и Стебель параллельно; их сбои — только в лог |
  | ошибка | любой | любой | 502, Стебель не вызывается |
  | не настроена | настроен | `1` | Стебель первым; его сбой — 502; потом сигнал в Telegram с номером Стебля (ответ ждёт его до 12 с), сбой сигнала — в лог |
  | не настроена | настроен | нет | Стебель и заявка целиком в Telegram почти параллельно; 502, только если не дошло никуда |
  | не настроена | не настроен | нет | только Telegram; его сбой — 502 |
  | не настроена | не настроен | `1` | 502 до отправки: заявку некуда сохранить |
- **Сессия Posiflora.** Access-токен кэшируется в памяти инстанса до `expireAt`
  (со сдвигом 30 c); параллельные заявки схлопываются в один логин. Протухший
  refresh-токен не роняет заявку — клиент логинится заново. На 401 делается
  один повтор с новой сессией. Пароль и токены вычищаются из логов.
- **Состав заказа.** С сайта приходит пожелание, а не корзина, поэтому заказ
  создаётся без позиций и с `budget: 0`, без привязки клиента: контакты
  (ФИО, телефон, ник, способ связи, категория, комментарий) складываются в
  `description`, который менеджер видит в карточке заказа.
- **Связи заказа.** Отправляем только то, что объявлено в схеме
  `POST /v1/orders`: `store`, `source`, `customer`, `createdBy`, `florist`.
  `lines`, `images`, `courier` и `updatedBy` есть лишь в примере из
  документации и несут пустые значения — не шлём, чтобы не ловить 422.
  `docNo` присваиваем сами: Posiflora требует поле непустым и не длиннее
  12 символов (иначе 422 с указанием на `/data/docNo`). Формат — префикс из
  `POSIFLORA_DOC_PREFIX` (по умолчанию `site`) плюс случайные
  шестнадцатеричные символы до 12 знаков: `site53da7243`. Префикс отделяет
  заказы с сайта от заведённых на кассе; из него берутся только строчные
  латинские буквы и цифры, не больше шести, так что лимит не сорвать даже
  длинным значением. Дату в номер не кладём — она и так есть в заказе, а
  12 символов лучше отдать под уникальность (при префиксе по умолчанию это
  свыше четырёх миллиардов вариантов).

- Цены поштучных позиций: `итог = prettyPrice(кол-во × цена/шт + упаковка)`,
  где `prettyPrice` округляет вверх до ближайшего `…90`.
- Карусель отзывов держит позицию в `(-half, 0]` по модулю половины ленты —
  контент задублирован, поэтому стык невидим; автопрокрутка и палец двигают
  одну и ту же координату.
- Фото витрины и раскрытых карточек — заранее скадрированные кадры 4:5 в
  `public/images/detail/` (композиция целиком, без полей). Заменили фото —
  нужен новый кадр там же; исходники без кропа лежат в `products/` и
  `catalog/`.
- На Windows с кириллицей в пути проекта Turbopack требует явный
  `turbopack.root` в `next.config.ts` — иначе паника «char boundary»
  в именах чанков.
